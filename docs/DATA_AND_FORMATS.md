# Data Preparation and File Formats

## Dataset Locations and Splits

Datasets are not bundled with this repository. The default root is `data/visual_grounding`; override it with `VISUAL_GROUNDING_ROOT`. Dataset-specific environment variables take precedence. All adapters are defined in `uncertainty/data/refcoco_grounding_dataset.py`.

| `--dataset` | Default subdirectory | Dataset-specific override | Original loader splits and conventions |
| --- | --- | --- | --- |
| `refcoco` | `RefCOCO` | `REFCOCO_ROOT` | `annotations/train.json[l]`, `validation.json[l]`, or `val.json[l]` |
| `refcoco_plus` | `RefCOCO+` | `REFCOCO_PLUS_ROOT` | Same as above; the saved `dataset_name` may be `refcoco+` |
| `refcocog` | `RefCOCOg` | `REFCOCOG_ROOT` | Same as above |
| `flickr30k_entities` | `Flickr30k` | `FLICKR30K_ENTITIES_ROOT` | `Entities/train.txt`, `val.txt`, `Sentences/`, `Annotations/`; single-box phrases only |
| `ref_adv` | `Ref-Adv` | `REF_ADV_ROOT` | `refcocog_adv_annotations.json` + `Images/`; deterministic 90%/10% split |
| `talk2car` | `Talk2Car` | `TALK2CAR_ROOT` | `annotations/train_commands.json`, `val_commands.json` + `images/` |
| `visual7w` | `Visual7W` | `VISUAL7W_ROOT` | `annotations/dataset_v7w_pointing.json` + `images/images/`; official train/val splits |
| `grefcoco` / `grefcoco_single` | `gRefCOCO` | `GREFCOCO_ROOT` | `annotations/grefs(unc).json`, `instances.json` + `images/`; single-target subsets, train / testA+testB |
| `ref_l4` | `Ref-L4` | `REF_L4_ROOT` | `ref-l4-val.parquet` → train, `ref-l4-test.parquet` → validation; image files in the root directory |

The Flickr30k Entities benchmark in the paper uses **`flickr30k_entities`**. The legacy `flickr30k` argument loads image-caption data rather than this grounding benchmark and cannot be substituted.

The RefCOCO family uses the JSON/JSONL format prepared by the source project and **does not directly parse the original `refs(...).p` files**. Use the source project's data directory or convert the official annotations into the structure below. The loader accepts `expression/referring_expression/phrase/question` as text fields. Boxes default to xywh; specify the format explicitly when possible:

```text
RefCOCO/
  images/
    example.jpg
  annotations/
    train.jsonl
    validation.jsonl
```

Example annotation:

```json
{"id":"ref-1","image_id":"image-1","image":"example.jpg","expression":"the object on the left","bbox":[10,20,100,140],"bbox_format":"xyxy","image_width":640,"image_height":480}
```

Different expressions for the same image must share the same `image_id` so that probe folds are grouped correctly. Sample IDs generated by the loader depend on annotation row order, so do not reorder annotation files after starting an experiment.

The gRefCOCO and Ref-L4 splits above follow the source project's explicit single-box protocol and do not cover every task in the full generalized referring-expression benchmarks. Multi-target and no-target samples are not forced into a single box. The adapter retains historical interfaces such as PR-Bench, but these are outside the paper's main nine-dataset pipeline.

## Generation Caches

The `train_generations.pkl` / `validation_generations.pkl` files written by `generate_answers.py` are dictionaries mapping `sample_id -> record`, with these main fields:

| Field | Contents |
| --- | --- |
| `question`, `context`, `answer`, `image` | Question, GT text representation, original PIL image, and related input data |
| `sample_metadata` | Dataset, split, source/image ID, image_path, GT box, and dimensions |
| `most_likely_answer.response` | Original low-temperature/greedy answer, kept fixed throughout subsequent processing |
| `most_likely_answer.prompt` | Exact generation prompt; always saved by this extraction |
| `most_likely_answer.accuracy/grounding_eval` | Original answer correctness and IoU, used only for supervision or evaluation |
| `most_likely_answer.probe_features` | Optional SEP/LRP/ICR/VIB/trajectory features |
| `responses` | High-temperature candidate answers and per-token log likelihoods |
| `lgd_uq` | OSD modes, auxiliary/target distributions, and the four `uncertainty` labels |

Raw auxiliary model responses and draw IDs are also saved in `*_lgd_references.pkl` and generation checkpoints. Preserve candidate boxes and sampling identities alongside the final `U_total`. Load pickle / torch files only from your own runs or trusted sources.

`collect-heads` writes `train/manifest.json`, `validation/manifest.json`, and `answer_free/*.pt`. Each entry in the manifest's `records` contains sample/group IDs, the prompt, frozen answer, four labels, and `feature_files.answer_free`. Each `.pt` file contains `sample_id`, a `feature` tensor of shape `[L,H,D]`, and an image digest. `fit-probes` also accepts features from other models in this format; sparse collection requires explicit, ascending `model_layer_ids`.

## Standalone OSD JSONL

`ceor osd` accepts inputs with existing target draws and does not generate target answers. It is a separate entry point from `generate_answers.py`; standalone JSONL outputs are not automatically converted into W&B generation files.

When calling auxiliary models, use one record per line:

```json
{"sample_id":"train-1","image_path":"images/example.jpg","question":"the object on the left","ground_truth_box":[0.1,0.2,0.4,0.6],"target_predictions":["[100,200,400,600]","[101,201,401,601]"]}
```

```bash
python -m ceor osd \
  --input data/train_with_target_draws.jsonl \
  --reference-config configs/auxiliary_models.local.json \
  --target-model /path/to/Qwen3-VL-4B-Instruct \
  --num-samples 10 --min-models 3 \
  --output experiments/outputs/train_osd.jsonl
```

`image_path` is resolved relative to the input JSONL directory. GT may use normalized xyxy coordinates, or pixel coordinates specified through `ground_truth_box_format` and the image dimensions. Set `prompt` when using a custom generation prompt; otherwise, the original grounding prompt is used.

If auxiliary outputs are already available, include them directly in each record:

```json
{"sample_id":"train-1","ground_truth_box":[0.1,0.2,0.4,0.6],"auxiliary_predictions":{"aux_a":[[0.1,0.2,0.4,0.6]],"aux_b":[[0.12,0.21,0.42,0.61]]},"target_predictions":[[0.6,0.2,0.9,0.6]]}
```

```bash
python -m ceor osd --input data/boxes.jsonl \
  --output experiments/outputs/osd_from_boxes.jsonl
```

Omitting `--reference-config` avoids all model calls. Each output record contains `sample_id`, `labels`, the legacy-compatible `lgd_uq` field, and `auxiliary_samples`. These examples illustrate the input format only; they are not paper samples or experimental results.

## Standalone CEOR Scoring JSONL

Each record must contain at least the following fields. GT and OSD labels are not required:

```json
{"sample_id":"new-1","image_path":"images/example.jpg","question":"the object on the left","frozen_answer":"[100,200,400,600]"}
```

If the answer was generated with a custom prompt, also provide the exact `prompt`. Model settings, image resizing, and the prompt must match normal generation.

```bash
python -m ceor score --input data/frozen_answers.jsonl \
  --model /path/to/Qwen3-VL-4B-Instruct \
  --key-layer experiments/outputs/refcoco/probes/key_layer.json \
  --output experiments/outputs/new_ceor.jsonl
```

This example has no clean-feature cache, so it performs two prefill passes: clean and masked. The output field `original_answer` preserves the original answer, and `ceor` contains the CEOR score. `response_available` and `missing_reason` support coverage reporting. For other models with two aligned arrays of head states, call `ceor.occlusion.occlusion_response(clean, masked, key_layer=..., model_layer_ids=...)` directly.
